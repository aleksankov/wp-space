# Единая система форм

Система поддерживает два ACF-блока Gutenberg с общей схемой полей, валидацией и отправкой:

| Режим | Блок | Назначение |
|---|---|---|
| На странице | `acf/form-custom` | Форма внутри содержимого или PHP-шаблона |
| В поп-апе | `acf/form-custom-popup` | Модальное окно, открываемое ссылкой по ID |

Оба блока отправляют `feedback_form_custom`. Старые `acf/form`, `.js-form` и AJAX action `feedback_form` удалены.

## Работа редактора

### Добавление формы

1. Откройте страницу или синхронизированный паттерн в редакторе Gutenberg.
2. Добавьте блок «Гибкая форма» или «Гибкая форма в поп-апе».
3. Заполните видимый заголовок и служебное название заявки.
4. Добавьте поля в требуемом порядке.
5. Выберите получателя, согласие, оформление и подпись кнопки.
6. Сохраните и проверьте форму на опубликованной странице.

Все поля необязательны на уровне конфигурации. Флажок «Обязательное» включайте только там, где пользователь действительно не может отправить форму без значения.

### Поля

| Тип | Для чего используется | Важные настройки |
|---|---|---|
| `text` | Имя, компания, специализация | Системное имя, подпись, длина |
| `tel` | Телефон | Серверная проверка формата |
| `email` | Электронная почта | Серверная проверка email |
| `textarea` | Комментарий | Максимальная длина |
| `select` | Ручной список | Варианты выбора |
| `products` | Глобальный список продуктов | Значения из «Настройки сайта → Формы» |
| `partners` | Глобальный список партнёров | Может участвовать в маршрутизации |
| `production` | Список выпускаемой продукции | Значения из доверенного источника темы |
| `file` | Резюме | `pdf`, `doc`, `docx`, размер 1–10 МБ |
| `hidden` | Контекст страницы | Заполняется сервером, не посетителем |

Системное имя должно содержать латинские буквы, цифры и подчёркивания. Не меняйте его после запуска интеграции без проверки: оно используется в заявке и валидации.

Пустые необязательные поля не выводятся в письме и заявке. Если изображение поп-апа скрыто или удалено, блок остаётся рабочим и не создаёт пустой `<img>`.

### Получатели

Редактор выбирает только тип получателя:

| Тип | Настройка сайта |
|---|---|
| `main` | Основной адрес заявок |
| `partner` | Адрес партнёрских заявок |
| `tech_partner` | Адрес технического партнёрства |
| `hr` | Адрес отдела кадров |

Адреса хранятся в «Настройки сайта → Формы». Email из браузера не принимается как получатель. В любом поле получателя, включая email дистрибьютора в `site_forms_partners`, можно указать несколько адресов через запятую, точку с запятой, пробел или перенос строки. Например: `first@example.org, second@example.org`. Сервер сначала разделяет строку, затем проверяет каждый адрес отдельно и удаляет дубли с сохранением порядка. Некорректные элементы пропускаются, не склеиваются с соседними адресами.

Если выбранный дистрибьютор не найден или у него нет ни одного корректного email, заявка не создаётся: показывается обычная ошибка. Исправьте настройку дистрибьютора, а не повторяйте отправку с теми же данными.

### Согласие

- «Глобальное» — текст берётся из настроек сайта.
- «Собственное» — текст задаётся в блоке.
- «Скрыто» — согласие не выводится.
- «Обязательное» — добавляет checkbox и серверную проверку.

### Модальные формы

Поле Popup ID задаётся без `#`, например `demo-vdi`. Кнопка открытия использует `href="#demo-vdi"`. На одной странице ID должен встречаться ровно один раз; повторный блок с таким ID не выводится.

Сохранены публичные ID: `demo-popup`, `demo-vm`, `buy-vm`, `demo-vdi`, `buy-vdi`, `partner-popup`, `tech-partner-popup` и `download_custom1`.

`demo-popup` хранится как синхронизированный блок `space-demo-popup` и подключён только на главной, Space VM, Space VDI, Space Client, Space Cloud и SpaceVM Essentials Plus Kit. Поддерживайте одну синхронизированную версию, а не отдельные копии.

### Формы главной и вакансий

- `space-home-form` выбран в «Настройки сайта → Формы» как источник формы главной.
- `space-vacancy-form` служит источником формы списка и отдельной вакансии.
- вакансия автоматически подписывает контекст текущей страницы на сервере;
- резюме необязательно по умолчанию, проходит проверку расширения, MIME-типа и размера.

## Что происходит при отправке

1. PHP нормализует конфигурацию блока и подписывает её HMAC.
2. Браузер отправляет поля, nonce и подписанную схему.
3. Сервер проверяет nonce, подпись, поля, согласие, контекст и файл.
4. Сервер получает адрес только из настроек сайта.
5. Создаётся запись CPT `mail`, затем `wp_mail` вызывается отдельно для каждого получателя.
6. Если все письма отправлены, открывается `feedback-success` и форма очищается.
7. Если запись уже создана, но хотя бы одно письмо не отправилось, открывается `feedback-saved` и форма очищается. Заявка сохранена; посетителю не нужно отправлять её повторно, даже если часть адресатов не получила письмо.
8. При ошибке до создания заявки, сбое сети или неверном ответе сервера открывается `feedback-error`, введённые значения сохраняются.

Системные окна результата остаются глобальными в `footer.php`. Статус доставки записан в метаполе `_space_form_delivery_status` записи `mail`: `sent`, `partial_failed` или `all_failed`. Счётчики есть в `_space_form_delivery_sent_count` и `_space_form_delivery_failed_count`. Найдите ID записи заявки в админке и выполните `wp post meta get <ID> _space_form_delivery_status` (для счётчиков — аналогично с соответствующим ключом). Метаполя с подчёркиванием не обязаны отображаться в редакторе записи. Не выполняйте автоматическую повторную отправку, поскольку часть писем могла дойти.

При сбое доставки PHP-журнал получает только ID заявки, статус и счётчики, без содержимого формы, email-адресов и SMTP-секретов. В непроизводственном окружении с `WP_DEBUG` также записываются обезличенные счётчики разбора получателей и успешной доставки.

## Безопасный предпросмотр

Проверьте обязательные поля, мобильную ширину и уникальность Popup ID. Для автоматической проверки используйте `php tests/form-recipients-test.php`, `php tests/form-submission-test.php` и Playwright-тесты: они перехватывают создание заявки/отправку письма либо `admin-ajax.php` и не создают настоящую заявку или письмо. Интеграционный `tests/form-server-test.php` создаёт записи `mail`; запускайте его только на тестовой базе, где можно удалить фикстуры. Не меняйте рабочие ACF-адреса ради проверки.
