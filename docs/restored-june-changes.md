# Восстановление потерянных июньских правок

База: GitHub `main`, `8de7d9602b747048276db47d3fd22b8834e17c32`.
Восстановлены изменения, потерянные в результате merge `d3965ba`.
Исходные реализации: `adc582e`, `8534581`, `218cc3a`, `2189fb7`, `1c2b26e`;
для файлов без последующих изменений использована проверенная версия `90c31d0`.

Восстановлены скрытие пустого раздела партнёров, две независимые группы
дистрибьюторов, управляемые соцсети главной с прежним fallback, MAX,
мобильная пагинация новостей, разделение рубрик и вкладка «Все», сайт
дистрибьютора на мобильных и малый баннер с необязательным текстом.
Пустая обёртка текста баннера теперь также не выводится.

Сентябрьские модули форм, настройки получателей и шаблон сервиса сохранены.
В главной заменена только часть с соцсетями; содержимое существующего
`<form>` оставлено побайтно неизменным. В настройках контактов добавлен
только MAX: существующие отделы и контакты футера сохранены.
Слайдер каждой группы использует собственную пагинацию.

CSS пересобран существующей цепочкой Sass → Autoprefixer → группировка
media queries. Версия основных CSS/JS изменена с `17` на `18`.

25 проверок рендеринга партнёров, независимых дистрибьюторов, баннера,
управляемых соцсетей, fallback и категорий прошли. Проверки получателей и
частичной/полной отправки заявок тоже прошли. Изменённые PHP-файлы прошли
lint, ACF JSON валиден.

`tests/popup-contract-test.php` ещё на исходном `main` завершался двумя
ошибками: наличие старого `acf/form` и его ACF-группы. Эти же две ошибки
сохранились; их устранение не включено в восстановление.

## После согласованного деплоя

1. В ACF синхронизировать изменённые Local JSON группы: «Контактная
   информация», главная, «Партнёры» и принадлежность рубрик разделам.
   Имена и ключи существующих полей сохранены. Время `modified` обновлено,
   чтобы изменения были доступны для синхронизации.
2. В настройках постоянных ссылок сохранить текущую структуру либо выполнить
   `wp rewrite flush` с активной темой. Структуру адресов не менять.
3. Очистить WP Rocket и при наличии внешний кэш.
4. Проверить два заполненных блока дистрибьюторов, пустую первую группу,
   отсутствие опубликованных партнёров, изменение соцсетей главной, ссылки
   MAX, новости и блог с разными рубриками и вкладкой «Все», пагинацию на
   ширинах 320/375/768 пикселей и баннер с пустым текстом.
5. Проверить формы в тестовом режиме без реальной рассылки и зафиксировать
   SHA/image digest выпущенной версии.

Production-база и админка при подготовке восстановления не изменялись.
Проверка всех сценариев на работающем WordPress с production-данными
остаётся частью проверки деплоя; isolated CLI-проверки её не заменяют.
